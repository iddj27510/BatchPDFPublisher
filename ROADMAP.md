## Mid-term (v10.x)

### .NET Add-in Migration

**Why considered:** Inventor 2027 supports .NET 8 add-ins without
recompilation. VBA has limits (single-threaded, no async/await, no DI).
Migration would enable:

- Background operations via Task.Run + CancellationToken
- Testability via xUnit + Moq
- SBOM generation via `dotnet sbom-tool`
- Code signing via `signtool`
- Proper COM interop without `Set oX = Nothing` idiom
- **System.Windows.Forms.Timer** — solves the Ctrl+Z auto-refresh
  limitation that VBA cannot address (AddressOf error 35010)

**What stays the same:**

- Business logic (validation, PDF export pipeline)
- Module structure (maps 1:1 to .NET classes)
- Test suite (40 tests migrate)

**What changes:**

- Entry point: `Run_BatchPDFPublisher` → .NET AddIn command
- UserForms: MSForms → WPF / WinForms
- VBA Module → .NET Class

**Blockers:**

- Inventor API surface (.NET interop required)
- Vault SDK (.NET native)
- Autodesk add-in manifest format

**When:** After v9.x stable + first portfolio iteration.

### Vault 2027 Integration (optional)

**Why considered:** Vault supports check-in / check-out flows.
Add-in could:

- Auto check-out IDW before PDF export
- Auto check-in generated PDF
- Log all Vault operations to AUDIT trail

**Blockers:**

- Vault licenses for end users
- Security analysis (see `ARCHITECTURE.md` section 26.9)

**When:** Not currently planned.
